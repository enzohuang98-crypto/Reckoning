# v0.4.19

v0.4.19 is a maintenance release. It removes the unused v1 explanation pipeline and other dead code and splits the three largest files into smaller modules. What the app does and what the AI is asked are unchanged from v0.4.18.

## 程式整理

- Removed the v1 Harness explanation pipeline, which only ran with the `XQA_EXPLAIN_PIPELINE=v1` environment variable, together with the tests, acceptance tool, types and settings that existed only for it (about 17,700 lines). The v2 pipeline is now the only explanation path.
- The analysis panel is split into an engine-analysis hook, an AI-explanation hook and a small hook for the rules that connect them; the panel component only assembles them. The engine and AI calls happen in the same order as before.
- The explanation fact table is split into a module folder (types, line replay, labels per language, prompt formatting). The text sent to the AI is byte-for-byte identical.
- The settings page keeps its layout; its state and IPC calls move into one hook per category (AI key and models, engines, data and system).

## Verification

- Typecheck (including tests), the full test manifest, security checks and the Windows CI job passed on the release commit.

## Windows 發布門檻

- The GitHub workflow must build the installer from this exact annotated tag and verify `latest.yml`, SHA-256, public download identity, and install/uninstall behavior before Latest promotion.
- Source keeps `forceCodeSigning: true`. No trusted Authenticode credential is configured, so a stable unsigned transition release requires the workflow's exact owner acknowledgement and remains subject to Windows SmartScreen.
- Windows Server 2022 and 2025 jobs are compatibility proxies. They do not establish clean Windows 10 or Windows 11 consumer-client acceptance.
