# 象棋 AI 分析講解 v0.3.8

v0.3.8 是 teacher-test evidence candidate。它把既有 Harness trace 升級成可以對接外部老師評分表的匿名證據鏈，但不建立另一套平行的老師測試資料庫，也不把自動測試誤寫成真人驗收。

## 主要改善

- 新增 main-memory teacher test run manifest，記錄 app version、release tag、product source commit、被核對安裝檔名稱與 SHA-256，以及 Windows runtime metadata。
- 正式 run 的 Harness trace 會附上 `testRunId`、保守的 `testCaseId`、canonicalization version 與匿名 `externalReviewId`；舊 trace 沒有這些欄位仍可讀取。
- `testCaseId` 保留完整 FEN、side-to-move、attached move、mode 與原始 question；question 只做 Unicode NFC 與 CRLF→LF，不折疊空白、不改標點、不做語義改寫。
- 安裝檔由 main 以非同步串流計算 SHA-256，hash 前後核對檔案大小與修改時間；export 只使用正向 allowlist，不寫出 API Key、Key digest、Authorization header、完整路徑、主機名或帳號。
- 設定頁新增獨立的「正式老師實測 run」控制，不增加 `AnalysisPanel` 或既有 AI IPC controller 的責任。

## 證據解讀

`artifactClaim` 表示本機所選檔案的位元組與使用者輸入的版本 metadata 相符，不等於可信簽章 provenance。老師姓名、角色、日期、簽名與詳細質性理由必須留在外部評分表，使用 `testRunId`／`testCaseId`／`externalReviewId` 對接。

## Windows 發布門檻

Release workflow 提供兩種明確模式：`teacher-candidate` 可建立刻意未簽章的 prerelease，必須揭露 SmartScreen 風險且永遠不升 Latest；`formal-release` 才會要求受信任 Authenticode 簽章、時間戳與獨立 Windows 10 22H2／Windows 11 client evidence。Server proxy、typecheck、unit test 或 engine E2E 都不能單獨取代 clean-client evidence。

## 已知限制

v0.3.8 在老師 pilot、臨時 API Key 零殘留、六案例雙機操作、象棋內容 rubric 與教學價值 gate 完成前，不得宣稱專業老師已驗證整體正確，也不得宣稱正式穩定版或可信發行者身分。
