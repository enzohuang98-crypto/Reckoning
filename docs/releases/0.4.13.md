# v0.4.13

v0.4.13 makes submitted-move explanations deterministic, keeps generation progress and errors in one place, and exposes safe diagnostics when OpenRouter cannot complete a full answer.

## Submitted explanation flow

- Opening the analysis screen no longer starts a full AI explanation. A unique submission ID is now the sole trigger, and one submission starts at most one generation.
- The submitted move and reason stay bound to the matching engine snapshot. Later engine refreshes cannot silently replace the position used by an active request.
- The input area now owns loading, elapsed time, cancellation, completion, failure, and explicit retry state. Previous successful output remains visible when regeneration fails or is cancelled.

## OpenRouter reliability and diagnostics

- Distinguish empty output, output truncation, returned-model mismatch, malformed responses, rate limits, network errors, and provider failures in UI diagnostics and allowlisted traces.
- Treat OpenRouter HTTP 200 error envelopes with 4xx or 5xx codes as provider HTTP failures without retaining upstream error details, prompts, credentials, or headers.
- Give the combined audit and five-section answer a 4,000-token output budget. Structured Nemotron Ultra requests reserve 1,000 reasoning tokens and exclude reasoning text from the returned JSON.
- Credential success text now states that the check proves a short reply, rather than claiming that a full explanation will complete.

## Update channel

- Keep stable unsigned transition releases synchronized with GitHub Latest only after the same workflow verifies version metadata, SHA-256, public downloads, and installer lifecycle checks.
- Retain `forceCodeSigning: true` in source. Any unsigned build remains an explicit workflow-only exception and carries a SmartScreen warning.

## Verification

- Unit, integration, renderer architecture, security, dependency audit, typecheck, and production-build checks passed in CI.
- Offline AI acceptance passed all 6 fixed cases and 358 soak cases.
- Live diagnosis verified OpenRouter account access, eligible free-model discovery, and Pikafish depth 17-19 analysis. The original long generation exhausted exact 2,500- and 4,000-token limits; the final post-fix attempts were blocked by repeated Nvidia endpoint 502 responses, including short probes.
