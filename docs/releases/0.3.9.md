# 象棋 AI 分析講解 v0.3.9

v0.3.9 是 v0.3.8 teacher-test candidate 的修正版。它修正 Harness teacher-test export 的 run isolation：只要 export 有目前的 `runManifest`，trace 與 regression case 就只會包含同一個 `testRunId`，避免把測試機上其他 run 的紀錄混入雙機證據包。v0.3.8 的 tag、Release 與 installer 不覆寫，仍保留為歷史候選證據。

## 主要改善

- `HarnessTraceStore` 的 teacher-test export 與 regression-case export 支援 `testRunId` 篩選。
- Settings export 以同一個 `runManifest.testRunId` 同時篩選 trace 與 regression case；沒有 teacher-test run 時保留既有的全量診斷匯出相容行為。
- 新增回歸測試，明確驗證前一個 run 的 trace 不會進入目前 run 的 export。
- teacher-test case 文件明確標示目前六題仍是 fixture-only，三個老師確認案例尚待外部提供或確認。

## 證據解讀

v0.3.9 仍是 teacher-test candidate，不代表老師雙機實測、臨時 API Key 零殘留、Windows 10／11 clean-client evidence、正式簽章或 Latest promotion 已完成。實際 test run 必須使用同一份公開 Release asset，並保存各機器獨立的 run manifest、六題 evaluation links、export SHA-256 與外部 rubric。

## Windows 發布門檻

Release workflow 的 `teacher-candidate` 模式仍刻意產出未簽章 prerelease，永遠不升為 Latest；`formal-release` 才要求受信任 Authenticode 簽章、時間戳與獨立 Windows 10 22H2／Windows 11 client evidence。Server proxy、typecheck、unit test、engine E2E 或本機乾跑都不能取代 clean-client 或真人教師門檻。
