# v0.4.14

v0.4.14 adds safe saved-model switching for OpenRouter and prepares desktop updates in the background without interrupting an active game or installing without an explicit restart.

## OpenRouter saved-model switching

- Discover eligible free text models for the currently saved OpenRouter credential and switch models without asking for the key again.
- Validate the saved credential, refresh the catalog, run a short generation with the selected model, and commit the binding only after every live step succeeds.
- Serialize competing switches with revision checks so stale or conflicting requests cannot overwrite the winning model binding.
- Snapshot the admitted model and credential for each AI request. An in-flight answer continues with its original binding even if the saved model changes meanwhile.
- Keep the previous answer and pending question visible when regeneration is cancelled, times out, is rate-limited, or encounters a provider failure. A 502 response offers a direct route back to model selection.

## Background update preparation

- Check GitHub Releases on the existing schedule and prepare an available update in the background by default while the app remains usable.
- Keep SDK `autoDownload` and automatic installation disabled. A downloaded update waits for the user to explicitly restart.
- Persist background preparation, skipped-version, and four-hour snooze preferences in the main process with atomic writes.
- Migrate legacy renderer preferences before the first automatic check, then remove the old localStorage values only after main-process persistence succeeds.
- Flush the latest in-memory app-data snapshot before restart. If saving fails or newer data appears during the flush, installation does not proceed until the newest snapshot is safely stored.
- Bound renderer update and data IPC operations with visible timeout errors instead of allowing controls to remain busy indefinitely.

## Updater verification

- Exercise the exported `electron-updater` NSIS implementation against a local HTTP fixture without patching dependencies or installing software.
- Verify a valid same-version cache avoids re-downloading the installer, a corrupt cache is rejected and can retry, and a changed SHA downloads new bytes.
- Verify successful differential transfer uses HTTP ranges and transfers fewer bytes than the full installer.
- Verify incompatible blockmaps perform exactly one full-download fallback.

## Verification

- Unit, integration, renderer architecture, security, dependency audit, typecheck, production build, and fake-engine E2E checks passed locally and in GitHub CI.
- The updater SDK fixture passed cache, corruption recovery, differential download, and full-fallback scenarios.
- Offline AI acceptance passed all 6 fixed cases and 358 soak cases.
- No live OpenRouter account call or installed-Windows update was used as evidence for this release preparation.
