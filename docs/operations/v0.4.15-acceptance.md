## 修改前截斷診斷

1. 正式完整講解的合併審查與五段正文呼叫實際送出 `max_tokens=4000`（程式內型別名稱為 `maxOutputTokens`），soft timeout 為 100 秒；暫時性錯誤最多再呼叫一次，且受同一次 Harness 的共享時間與 token 預算限制。
2. 修改前只有精確 Ultra 模型的 JSON 請求有 `reasoning.max_tokens=1000`；`nvidia/nemotron-3-super-120b-a12b:free` 沒有相同限制。
3. 2026-09-19 查核 OpenRouter 官方模型與參數資料：該精確 Super 模型列為免費模型，支援 `max_tokens`、`reasoning`、`reasoning_effort`、`response_format` 與 structured outputs；endpoint 列出的 reasoning 預設為啟用，支援 low／medium effort。官方 reasoning 說明也指出 `reasoning.exclude=true` 只是不回傳 reasoning，不能視為不消耗 reasoning tokens。
4. 本執行環境沒有正式 SecretStore 與已保存 OpenRouter key，因此修改前的本輪真實 `finish_reason`、completion tokens 與 reasoning tokens均為「未提供」。歷史 `generation_incomplete` 只作問題線索，不冒充本輪實測。
5. 依現有呼叫流程，歷史截斷最可能發生在 `initial_combined`（合併審查與正文）階段；初次成功不會再進 writer／repair。缺少本輪 provider trace，故這是流程定位，不是已證實的外部回應結果。

## 修正摘要

- 以實際引擎比較資料建立 `same_move`、`near_equivalent`、`evidence_backed_difference`、`insufficient` 四種狀態；沿用既有近似等值分類，不新增分差門檻。
- 同首選時改用正向五段標題與契約，禁止強迫寫失誤、懲罰或「更好的同一著法」。
- 不足聲明只豁免明確且有限的不適用要求；同段其他實質斷言仍須通過因果與證據規則。
- evidence／finding 除了 ID 存在，還會核對局面、方別、所屬變例、引用著法與對手回應的 scope。
- 最終進度只陳述結構、引用連結與可計算棋盤事實已檢查，不把模型解釋宣稱為獨立證實。
- 精確 Super 與 Ultra 的 JSON 請求使用有限 `reasoning.max_tokens=1000`；其他模型或文字輸出不誤套。仍拒絕 `finish_reason=length`、空正文與不完整 JSON。
- 安全 trace 只記模型、階段、請求輸出預算、reasoning 設定、可取得 token 數、finish reason、耗時、錯誤分類及呼叫次數，不記 key、header、prompt、原始回應或 reasoning 內容。
- 未簽章候選建立與 Latest promotion 拆成兩個 workflow；promotion 只核對並提升已驗收資產，不重建、不覆寫。
